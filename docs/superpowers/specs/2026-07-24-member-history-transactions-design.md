# ธุรกรรมรวมในหน้า Member History

## เป้าหมาย

ปรับ `/member/history` ให้รวมประวัติการเงินและคะแนนของสมาชิกไว้ในหน้าเดียว โดยแสดงแอปแยกกันชัดเจน ไม่ใช้รายการรวมทุกแอป และให้กรองข้อมูลตามแอป ประเภท รูปแบบ และสถานะได้

## ขอบเขต

- คงหน้าประวัติเดิมของแต่ละแอปไว้เหมือนเดิม
- ปรับเฉพาะส่วนธุรกรรมรวมใน `src/content/MemberHistory/index.tsx`
- ใช้ข้อมูลจาก API เดิมที่มีอยู่ก่อน
- รองรับข้อมูลคะแนนจาก Live ปัจจุบัน และเตรียมโครงสร้างสำหรับคะแนนจาก Admin กับการสำเร็จ Level

## รูปแบบข้อมูลกลาง

ทุกรายการจะถูกแปลงเป็นข้อมูลกลางที่มี `id`, `appId`, `appName`, `type`, `format`, `item`, `status`, `amount`, `note`, `createdAt` และ `source`

- `appId` และ `appName` มาจาก `organization_id` และข้อมูลสังกัดของสมาชิก
- ถ้า API ไม่มีข้อมูลสังกัด ให้แสดง `ไม่ระบุแอป` เท่านั้น ไม่ใช้ `รวมทุก App`
- `type` แบ่งเป็นรายรับและรายจ่าย
- `format` รองรับเงิน, Coin PX และคะแนน
- `source` แยก Coin, Live, Admin และ Level เพื่อรองรับการเชื่อมข้อมูลจริงในอนาคต

## หน้าจอ

Filter card รองรับ responsive และมีตัวเลือก:

- แอป: ทุกแอป, แอปจริงของสมาชิก และรายการระบบกลางที่มีข้อมูล
- ประเภท: ทั้งหมด, รายรับ, รายจ่าย
- รูปแบบ: ทั้งหมด, เงิน, Coin PX, คะแนน
- สถานะ: ทั้งหมด, สำเร็จ, รอดำเนินการ, ปฏิเสธ, ไม่ระบุ
- ปุ่มล้างตัวกรองคืนค่าเริ่มต้นทุกตัว

ตารางใช้คอลัมน์ วันเวลา, ประเภท, แอป, รูปแบบ, รายการ, สถานะ, ยอด และหมายเหตุ โดยเรียงรายการใหม่สุดก่อนและเลื่อนแนวนอนได้บนหน้าจอเล็ก

## Data Flow

1. โหลด profile และสังกัดของสมาชิก
2. โหลดประวัติ Coin ของแต่ละสังกัดด้วย hook แบบ lazy แล้วแปลงเป็นรายการกลาง
3. โหลดธุรกรรมคะแนน Live แล้วแปลงเป็นรายการกลาง
4. รวม เรียงตามวันเวลา และกรองด้วย state ฝั่ง client
5. แสดง loading, empty และกรณีข้อมูลบาง source โหลดไม่สำเร็จโดยยังคงแสดง source อื่นได้

## ข้อจำกัด Backend

คะแนนแจกโดย Admin และคะแนนจากการสำเร็จ Level ยังต้องมี endpoint หรือ field ที่ระบุ source, app และเวลาให้ชัดเจน เมื่อยังไม่มี endpoint หน้าจอจะเตรียม adapter และชนิดข้อมูลไว้ แต่จะไม่เดาข้อมูลจริงจากธุรกรรมประเภทอื่น
